# 密码与访问基础（模板）

完整策略中的六节：范围、口令组成、多因素认证、特权访问、远程访问、凭证失陷。决定记号仍在反引号里。把它们换成你选定的值。在抄数字或设置名之前，阅读 NIST Special Publication 800-63B，并核对身份提供者的文档。说明里的邮箱使用 example.com。填好的节选写的是 Harbor & Pine Cooperative。

## 目的与范围

写明谁会得到账号，以及这些账号能到达哪些系统。覆盖员工和承包人员、身份提供者、他们登录的应用、办公局域网，以及管理用的堡垒机。写明人员在选择口令、申请访问或离职时遵守本策略，运维人员在创建账号和复核登录时遵守本策略。

范围要短到新员工能看出某个系统在不在里面。增加系统时改这一节，不要靠旁边一句口头约定。
## 口令组成

日常口令至少 `ORG_MIN_LENGTH` 个字符。特权口令至少 `ORG_ADMIN_MIN_LENGTH` 个字符。两者都是组织的决定。在把其中一个当成公开标准里的最短长度之前，先阅读 NIST Special Publication 800-63B。要求身份提供者至少接受 64 个字符。允许空格。不要求字符类别的组合。

允许使用口令管理器，并允许在登录页粘贴。用身份提供者的禁用口令表检查新口令。这张表如何加载取决于厂商。请核对身份提供者的文档。本模板不写厂商名称或 API 字段。

登录限流是 `ORG_LOCKOUT`。写上你要配置的失败次数和锁定时长。设置名称先看 IdP 文档。
## 多因素认证

远程访问和每一次特权登录，现在就要求第二因素。写上你实际登记的那种因素。填好的例子使用身份提供者的应用提示，并且不发放硬件令牌。

从 `ORG_MFA_DATE` 起，每个账号都要求这个第二因素，包括来自办公局域网的登录。因素如何登记，要看 IdP 文档。本模板不写登记 API。
## 特权访问

特权工作使用单独的管理账号。日常账号不能加入管理组。管理账号登录使用多因素，包括从办公局域网登录。

只有主管和策略负责人都批准工单之后，才创建管理账号。管理口令满足 `ORG_ADMIN_MIN_LENGTH`。持有人可以把它放进口令管理器。它不进入个人便签或工单。
## 远程访问

划定办公局域网，并写明从其他地方进行管理时走指定的堡垒机并且需要多因素。地址用你自己的清单。填好的例子使用 RFC 5737 文档地址 192.0.2.10 和 RFC 1918 局域网 10.8.0.0/24，因为那个合作社是虚构的。

管理页面在局域网内外都需要多因素。应用的普通使用按日期 `ORG_MFA_DATE` 执行。管理员的 SSH 经过堡垒机。主机防火墙的细节放在主机标准里。
## 凭证失陷

把顺序写下来，并按顺序执行。

1. 停用账号，或停用该服务凭证。
2. 撤销活动会话。
3. 轮换口令，以及该账号能够读到的每一个秘密。
4. 把账号名和发现暴露的时间通知策略负责人。
5. 复核此前 14 天的登录日志。
6. 新秘密已经存好并且应用已经使用它之前，服务凭证保持停用。

口令暴露的那个人按口令组成一节重新选择，并且不复用最近 `ORG_HISTORY_DEPTH` 个口令。策略负责人决定本策略要不要提前复审。
